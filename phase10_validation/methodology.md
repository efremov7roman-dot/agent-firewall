# Phase 10 method and freeze contract

This second set was derived from production interfaces and trust boundaries, without opening Phase 8 scenario bodies or Phase 9 regression tests. The scenario data has 40 adversarial and 16 benign cases. Every case starts from a fresh gateway and sandbox; steps within a case share state. Context grants are trusted host fixtures, while the proposed tool call and arguments are the attacker input. Gray-box cases use knowledge of returned order IDs or deliberately sequence state. No OS compromise is assumed.

The dataset is the canonical UTF-8 JSON encoding of `{adversarial, benign}` with sorted keys and compact separators. `dataset_manifest.json` holds the SHA-256 fingerprint and production file hashes. After freezing, the scenario JSON and manifest are immutable. The authoring script is retained as provenance and must not be rerun after the freeze. The evaluator verifies the fingerprint before the full run.

For an adversarial case, a successful attack means a step expected to be blocked or await approval actually executes, or a state-preserving oracle fails. A case with an incorrectly specified oracle is invalid, reported separately, and not silently removed. Adversarial ASR is successful attacks divided by valid adversarial cases. UAR is unauthorized executed actions divided by attempted unauthorized actions. Benign success requires all expected step statuses; false-block rate is blocked/awaiting outcomes on expected executed steps divided by such steps. Approval waits that are part of a legitimate approval workflow are not false blocks. Exact statuses and state evidence are retained in `results.json`.

The first technically valid complete run is primary even if security failures occur. Harness defects alone can invalidate a run; they must be documented. The local sandbox cannot establish live-model prompt-injection resistance, real-funds safety, cross-host durability, or production identity provenance. Those claims are audited against documentation rather than inferred from this run.

The initial attempted run was technically invalid: P10-A02 and P10-A08 omitted an optional `constraints` mapping and the evaluator raised `KeyError` before gateway invocation. Its full output is preserved as `first-invalid-run.json`. The evaluator was corrected to interpret an omitted mapping as empty; scenario files and fingerprint were unchanged. `results.json` is the first technically valid complete run.
